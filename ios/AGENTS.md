# Agent Guidelines for `mobile/ios/`

This file governs AI agent behaviour inside the Livtet iOS app. Read it together
with the root [AGENTS.md](../../AGENTS.md) and the
[mobile/ios/README.md](README.md). The README documents the app surface; this
file captures the rules an agent must follow.

The iOS app is a **separate product** that shares the Livtet brand name. It is
not a Tauri target, not a "mobile build of Tauri", and Tauri configuration
(`.browserslistrc`, `tauri.conf.json`, `packages/livtet-tauri-web/`) is
irrelevant to it.

## Required Skills

- `guardrails` — never restart, start, or kill the dev server or the Xcode build
  pipeline. Always ask before running `mise run ios-build`,
  `mise run ios-run-simulator`, or any Xcode/xcodebuild command.
- `mise-tools` — required when a `mise.toml`-declared binary returns
  `command not found` (for example `uniffi-bindgen` or `xcodegen`).

## Commands

The iOS build chain is macOS-only. Linux worktrees cannot run `ios-*` mise
tasks; treat them as unavailable in that environment. From a macOS worktree:

```bash
mise run ios-dev-init   # xcodegen + pod install (one-time, after spec/dependency changes)
mise run ios-build      # builds the Rust FFI static libs, packages the xcframework, xcodebuild
mise run ios-bindings   # regenerate UniFFI Swift bindings (after Rust FFI changes)
mise run ios-run-simulator
mise run ios-lint
mise run ios-test
mise run ios-clean
```

`mise run dev-setup` installs the full toolchain (Xcode CLT, CocoaPods, Ruby,
SwiftLint, xcodegen, uniffi-bindgen) and configures git hooks.

## UniFFI Bindings

The Swift bindings under
`LivtetKit/Sources/{LivtetKitFFI,LivtetKitFFI_types,livtet_ffiFFI,livtet_ffi_typesFFI}/`
are generated by `uniffi-bindgen`. Treat them as build artifacts: do not
hand-edit, and re-run `mise run ios-bindings` after every change to
`crates/livtet-ffi/` or `crates/livtet-ffi-types/`. The xcframework at
`LivtetKit.xcframework/` is regenerated by `mise run ios-build`; delete it to
force a clean rebuild.

## iOS Project Naming

The product name and every iOS path component that contains it is the **6-letter
form `Livtet`** (L I V T E T). The correct 6-letter spelling is the only
acceptable form for the product name, directory names, file basenames, the Xcode
project bundle name, the unit-test target name, the bundle identifier, and every
other identifier in the iOS project.

Canonical paths (after the iOS scaffold landed on `ios/integration`):

- `mobile/ios/Livtet/` — app sources (`LivtetApp.swift`, `Models/`, `Services/`,
  `Utilities/`, `Views/`, `Resources/`)
- `mobile/ios/LivtetUnitTests/` — XCTest unit tests
- `mobile/ios/Livtet.xcodeproj/` — Xcode project bundle
- `mobile/ios/LivtetKit/` — FFI xcframework package (the `Kit` suffix is
  intentional; do not rename)
- `mobile/ios/project.yml` — XcodeGen spec
- `mobile/ios/Podfile` — CocoaPods manifest
- `mobile/ios/.swiftlint.yml` — SwiftLint configuration

macOS APFS is case-insensitive, so case-only renames require a two-step POSIX
`mv` dance: first move the directory to a clearly-different temp name (e.g.
`_livapp_tmp`), then move it to the final name. Bash commands that resolve path
components case-insensitively can silently write to the wrong directory on
case-insensitive APFS volumes, so always verify the target path with `ls` after
creating or renaming a directory.

When a tool reports a path that appears to contain the product name with extra
letters, treat it as a typo and stop rather than echoing it back in your
response. The correct form is always exactly 6 characters.

## Generated Files and Artifacts

- `LivtetKit.xcframework/` — produced by `mise run ios-build`. Gitignored.
- `LivtetKit/Sources/{LivtetKitFFI,LivtetKitFFI_types,livtet_ffiFFI,livtet_ffi_typesFFI}/`
  — produced by `mise run ios-bindings`. Generated; do not hand-edit.
- `Livtet.xcodeproj/` — generated by XcodeGen from `project.yml`. Do not
  hand-edit; modify `project.yml` and re-run `mise run ios-dev-init`.
- `Pods/`, `Podfile.lock`, `.derivedData/` — CocoaPods and Xcode build outputs.
  Gitignored.
